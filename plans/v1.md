# Arodnap v1 Plan

## Summary

v1 turns Arodnap from a normalized-benchmark script into a build-backed tool for standard single-module Gradle Java repositories. The tool operates on a temporary workspace copy, owns the outer analysis and repair loop in Python, keeps Java-based analysis and transformation tools intact, and emits patches and machine-readable results without mutating the original repo by default.

This is the first milestone that should be usable by someone outside the original benchmark workflow. It is intentionally narrow:

- standard single-module Gradle Java projects only
- temp workspace copy by default
- no field enhancement stage
- one internal legacy normalized path retained only for migration and regression coverage

## Public CLI

The public CLI surface for v1 is:

```bash
arodnap analyze /path/to/repo
arodnap infer /path/to/repo
arodnap repair /path/to/repo
arodnap apply --patch-dir ./arodnap-out/patches /path/to/repo
```

### Command Semantics

- `analyze`: run a single build-backed RLC pass with no source transformation stages and no WPI loop. Output diagnostics and metadata only.
- `infer`: run `reanalyze(workspace)` once. Preserve inferred annotation outputs, diagnostics, and metadata. Do not run repair stages.
- `repair`: run the full staged pipeline defined below.
- `apply`: apply previously emitted patches to the original repo. This is the only public command that mutates the original repo.

### Required CLI Flags In v1

- `--out-dir`: defaults to `./arodnap-out`
- `--keep-workspace`: when set, do not delete the temporary workspace
- `--build-args`: extra build arguments forwarded to the WPI and Gradle adapter flow
- `--compile-target`: override the compile target used by the WPI and Gradle adapter flow
- `apply` only:
  - `--patch-dir`: required path to a patch bundle

No other public flags are required in v1.

## Supported Scope

### Supported

- standard single-module Gradle Java repos
- conventional main sources under `src/main/java`
- one selected root project only
- Arodnap-owned temporary workspace copy
- patch emission and later application

### Explicitly Out Of Scope For v1

- field enhancement
- public support for normalized benchmark layout
- Maven
- Ant
- multi-module Gradle
- generated-source-heavy repos
- custom source-set layouts
- direct classpath mode for RLFixer
- automatic mutation of the original repo

## Current Repo Corrections

These repo truths must be reflected in implementation and documentation:

- `run_arodnap.py` still invokes field enhancement. That is legacy behavior and not part of v1.
- `run_arodnap.py` still mutates the target repo directly. That is legacy behavior and not part of v1.
- `BenchmarkCleaner.restore_benchmark()` currently performs destructive git cleanup. That behavior must not exist in the public v1 flow.
- `helpers/wpi.sh` is a normalized-layout helper and must not become the build-backed WPI abstraction.
- `CloseInjector.py`, `OwningFieldModifier.py`, and `utils.compute_p_flag()` assume patch files live under `src/`. Those assumptions must be abstracted behind stage wrappers.
- `utils.run_rlfixer()` currently relies on argparse long-option abbreviation when invoking `RLFixerRunner.py`. New code must use exact option names only.
- `SourceProjectCompiler.compile_benchmark_if_patched()` currently recompiles unconditionally. In the new pipeline, recompilation must be controlled by explicit pipeline state.

## Architecture

### Language Split

- Python remains the orchestrator, CLI, adapter layer, workspace manager, results manager, and stage runner.
- Java remains the home for JavaParser-based transforms, WALA-based RLFixer logic, and any tool that is already packaged as a jar or Java subproject.

### Core Primitive

The new analysis primitive is:

```text
reanalyze(workspace) =
  run build-backed WPI on the current workspace
  run RLC again using the latest inferred outputs
  return a structured result with diagnostics, inference outputs, and derived adapter metadata
```

All repair stages that can change sources must follow:

```text
apply_stage(...)
if stage_result.rerun_required:
  state.current = reanalyze(workspace)
```

No stage is allowed to invoke RLC or WPI directly outside this abstraction.

### Assumption Discipline

v1 does not eliminate assumptions. It eliminates hidden assumptions.

All new code must follow this rule:

- discover facts from the build system and workspace, not from legacy path conventions
- normalize tool-specific outputs into stable Arodnap-owned artifacts
- verify emitted artifacts before treating them as valid outputs
- fail closed when discovery or verification does not succeed

Concretely:

- build facts must come from the Gradle adapter, not from hard-coded `src/`, `lib/`, or `build/` guesses outside the adapter contract
- supported project shapes are explicit contracts, not inferred best-effort guesses
- raw stage patches must be normalized into repo-root-relative artifacts before they are exposed outside a stage wrapper
- final patch bundles must be dry-run validated against a clean copy of the original repo before they are reported as applyable
- discovered build facts must be persisted in machine-readable metadata and reused by later stages rather than re-guessed

The only acceptable v1 assumptions are declared preconditions for supported repos. Unsupported or ambiguous repos must fail with an explicit unsupported-project error.

## Decision-Complete Interfaces

### `RunConfig`

`RunConfig` is an immutable dataclass with these fields:

- `command: Literal["analyze", "infer", "repair", "apply"]`
- `repo_root: Path`
- `out_dir: Path`
- `keep_workspace: bool`
- `workspace_mode: Literal["copy"]`
- `build_args: list[str]`
- `compile_target: str | None`
- `patch_dir: Path | None`
- `cf_root: Path`
- `close_injector_jar: Path`
- `owning_field_jar: Path`
- `rlpatcher_jar: Path`
- `timeouts: Timeouts`

`RunConfig` is created once per invocation and never mutated.

### `PipelineState`

`PipelineState` is a mutable orchestration object with these fields:

- `config: RunConfig`
- `workspace_root: Path`
- `build_system: Literal["gradle"]`
- `adapter_name: str`
- `current_analysis: ReanalyzeResult | None`
- `stage_history: list[StageResult]`
- `artifacts_root: Path`
- `final_patch_manifest: Path | None`
- `legacy_regression_enabled: bool`

### `ReanalyzeResult`

`ReanalyzeResult` is the sole output of `reanalyze(workspace)` and must contain:

- `workspace_root: Path`
- `label: str`
- `wpi_log_path: Path`
- `inference_dir: Path`
- `diagnostics_path: Path`
- `warning_count: int`
- `source_files_file: Path`
- `app_classes_file: Path`
- `classpath_entries_file: Path`
- `adapter_metadata_path: Path`

`inference_dir` points to the stabilized inferred output for that workspace state, not to a transient intermediate directory.

### `StageResult`

Every stage returns a `StageResult` dataclass with:

- `stage: str`
- `changed: bool`
- `changed_files: list[str]`
- `rerun_required: bool`
- `artifacts: dict[str, str]`
- `notes: list[str]`
- `success: bool`

Each stage also writes a matching `stage_result.json` file with the same shape.

## Output Layout

The default output layout under `./arodnap-out` is:

```text
arodnap-out/
  report.json
  manifest.json
  diagnostics/
  inference/
  logs/
  stages/
    close_injector/
    owning_field/
    rlfixer/
    rlpatcher/
  patches/
    manifest.json
```

### Required Contents

- `report.json`: top-level machine-readable run summary
- `manifest.json`: top-level run manifest with workspace, config, and selected adapter information
- `diagnostics/`: one RLC diagnostics file per analysis point
- `inference/`: preserved stabilized inferred outputs per analysis point
- `logs/`: WPI, adapter, and orchestrator logs
- `stages/<name>/`: stage-local logs, patch files, and `stage_result.json`
- `patches/manifest.json`: patch bundle manifest used by `apply`

## Gradle Adapter

### Detection

The Gradle adapter supports a repo only if all of the following are true:

- the repo root contains `build.gradle` or `build.gradle.kts`
- the repo root is the selected analysis root
- sources are under `src/main/java`
- the project can compile with a standard main compile target
- the adapter does not detect multi-module structure

If the repo is ambiguous or unsupported, fail with an explicit unsupported-project error. Do not guess.

This detection block is a declared support contract, not a heuristic. If any condition cannot be proved from Gradle-backed facts, the adapter must reject the repo.

### Build Tool Selection

- Prefer `./gradlew` if present and executable in the target repo.
- Fall back to `gradle` only if the wrapper is absent.
- If neither is available, fail with a clear prerequisite error.

### Source Files

For v1, source files are exactly all `*.java` files under `src/main/java`. Do not include test sources. Do not include generated sources in v1.

The adapter must write them to a newline-delimited file and return that path in `ReanalyzeResult.source_files_file`.

### Application Classes

After compilation, application classes are generated from `build/classes/java/main/**/*.class`.

Rules:

- include top-level and nested classes
- encode nested classes using `$`
- exclude `module-info.class`

The adapter must write the resulting fully qualified names to a newline-delimited file and return that path in `ReanalyzeResult.app_classes_file`.

### Binary Classpath

The adapter must compute a classpath file containing:

- main compiled output directories
- resolved dependency jars required for analysis

Implementation contract:

- create a transient Gradle init script in the workspace
- register a task named `arodnapPrintMainClasspath`
- print newline-separated absolute paths for the main output plus compile classpath entries
- parse that output into `classpath_entries_file`

No direct parsing of Gradle cache internals is allowed in v1.

All adapter-derived facts must also be persisted in `adapter_metadata_path` so later stages consume explicit metadata rather than reconstructing build state.

## WPI And RLC Execution

### WPI

The v1 WPI runner must invoke the official Checker Framework `wpi.sh` from the vendored Checker Framework distribution, not the current repo-local helper script.

Use:

- `checker_framework/checker-framework-3.49.0/checker/bin/wpi.sh`

Required behavior:

- invoke against the workspace root
- map `--build-args` to `-b`
- map `--compile-target` to `-c`
- capture stdout and stderr into `logs/`
- preserve the stabilized inferred output directory under `inference/`
- preserve enough metadata to identify which analysis point produced which inferred output

### RLC

After WPI stabilizes for a given workspace state, run a separate RLC pass using:

- source files from the Gradle adapter
- binary classpath from the Gradle adapter
- `-Aajava` pointing to the stabilized inferred output directory

Do not rely on:

- `src/` as the only source root beyond the adapter contract
- `lib/` as the dependency source
- mutable process-global constants

## Stage Sequence

The v1 `repair` pipeline is:

1. Create a temporary workspace copy of the target repo.
2. Detect the Gradle adapter and validate the repo shape.
3. Run `reanalyze(workspace)` and store it as the initial analysis result.
4. Run the close-injector stage against the workspace and current diagnostics.
5. If close injector changed files, rerun `reanalyze(workspace)` and store the new result.
6. Run the owning-field stage against the workspace and current diagnostics.
7. If owning field changed files, rerun `reanalyze(workspace)` and store the new result.
8. Generate the RLFixer compatibility bundle from the final workspace state.
9. Run RLFixer once on the final workspace state.
10. Run RLPatcher materialization.
11. Emit `report.json`, patch manifests, diagnostics, logs, and preserved inference outputs.

Field enhancement is not part of this sequence.

## Stage Contracts

### Close Injector Stage

Input:

- workspace path
- current diagnostics path
- stage output directory

Output:

- whether a patch was generated
- which files changed
- stage-local patch artifact
- stage-local log

Implementation notes:

- wrap the existing Java tool
- do not let the wrapper assume that output patches live under `workspace/src`
- normalize stage artifacts into `stages/close_injector/`
- rewrite any tool-emitted patch paths into repo-root-relative paths before exposing them to later pipeline steps

### Owning Field Stage

Input and output are the same shape as close injector.

Implementation notes:

- wrap the existing Java tool
- do not expose the current patch-path assumptions outside the stage wrapper
- normalize stage artifacts into `stages/owning_field/`
- rewrite any tool-emitted patch paths into repo-root-relative paths before exposing them to later pipeline steps

### RLFixer Stage

This stage does not mutate source files directly in v1. It produces RLFixer fix suggestions and debug output from the final workspace analysis state.

Outputs:

- `fixes.txt`
- `debug.txt`
- compatibility bundle metadata

### RLPatcher Stage

This stage materializes concrete source patches from RLFixer suggestions using the final workspace state.

Outputs:

- individual patch files
- stage log
- patch manifest entries

## RLFixer Compatibility Bundle

v1 keeps RLFixer itself unchanged and synthesizes the legacy on-disk inputs it expects.

The compatibility generator must produce:

- `info/classes`
- `info/sources`
- `jarfile/<project>.jar`

Inputs to the generator:

- final workspace source files file
- final workspace app classes file
- final workspace classpath entries
- final workspace compiled outputs

Jar generation requirements:

- compile or reuse final workspace main outputs
- package compiled classes plus required dependency contents into a compatibility jar
- store bundle artifacts under `stages/rlfixer/compat_bundle/`

The compatibility generator is the only v1 place allowed to emulate the old benchmark layout.

## Apply Command

`apply` consumes `patches/manifest.json`.

Patch bundle requirements:

- each patch entry records:
  - patch file path
  - stage
  - strip level
  - target root relative to repo root
  - changed files
  - preimage hashes for changed files

Apply behavior:

- run a dry-run patch validation first
- apply patches sequentially only if validation succeeds
- fail on the first patch error
- do not require git
- treat dry-run failure as a patch-generation failure, not as a recoverable apply-time warning

Patch format requirement:

- all emitted patches must be usable against the original repo root using the manifest-provided strip level
- final patch bundles are not valid outputs until they pass dry-run validation against a clean copy of the original repo

Patch tool compatibility requirement:

- v1 must make patch-tool behavior explicit rather than assuming Linux-only GNU `patch`
- prefer GNU `patch` when available
- on macOS, support Homebrew-style GNU `patch` installations such as `gpatch` without requiring users to replace `/usr/bin/patch`
- record the selected patch binary and version in stage/apply logs
- if only an incompatible patch implementation is available for the required flags or patch shape, fail with a clear prerequisite error instead of silently applying with different semantics

## Acceptance Criteria

- `arodnap repair` works end to end on a standard single-module Gradle repo.
- The original repo is not modified by default.
- `reanalyze(workspace)` is the only analysis rerun primitive used by mutation-capable stages.
- Field enhancement is absent from the v1 public pipeline.
- RLFixer still runs through a compatibility bundle rather than a direct rewrite.
- Outputs are preserved under a stable `arodnap-out/` layout.
- Patch application behavior is explicit and reproducible across Linux and macOS, or fails with a clear prerequisite error when the available `patch` implementation is unsupported.
- There are no unresolved milestone-splitting or architecture decisions left for the implementer.

## Assumptions

- The vendored Checker Framework remains the source for the official `wpi.sh` used in v1.
- Standard single-module Gradle is defined by convention and validated by adapter checks rather than broad Gradle model support.
- The legacy normalized-project path remains internal only until the v1 flow is stable and regression coverage is in place.
